# MZSAE Project Governance

MZSAE operates under a Benevolent Dictator For Life (BDFL) model.

## BDFL

The BDFL is **Mohammed Hossam Zahran**. The BDFL has the final say on all technical decisions, architecture directions, and project strategy.

## Decision-Making Process

* Technical decisions are ultimately made by the BDFL.
* Community input is highly valued and gathered via GitHub Discussions and issue tracking.
* We prioritize open discourse and technical merit, but the BDFL resolves any stalemates.

## Contribution Tiers

1. **Contributor**: Anyone who has opened a PR, issue, or contributed to discussions.
2. **Committer**: Contributors who have demonstrated a strong understanding of the codebase. Requirements: at least 2 merged Pull Requests and domain expertise (e.g., Metal kernels, neuromorphic ML). Committers have triage rights and can review PRs.
3. **Maintainer**: Core team members with write access to the repository, capable of merging PRs and guiding the project's day-to-day operations. Appointed by the BDFL.

## RFC Process for Breaking Changes

For major architectural changes or breaking API modifications, we follow an RFC (Request for Comments) process:
1. Open a discussion thread or an RFC issue detailing the proposed change, its motivation, and its impact.
2. The proposal undergoes a **7-day comment period** for community feedback.
3. The BDFL will review the feedback and make the final call on accepting, modifying, or rejecting the RFC.

## Code of Conduct Enforcement

The Code of Conduct is enforced by the project leadership. Violations can be reported via email or GitHub issues. The BDFL and Maintainers are responsible for evaluating reports and taking appropriate action as outlined in the `CODE_OF_CONDUCT.md`.
